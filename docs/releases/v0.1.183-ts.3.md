# TokenSupply v0.1.183-ts.3

## Highlights

- 部署器重启自愈：修复"发布切换后应用容器不再随服务器重启自启"的根因（`docker kill --signal=USR1` 会给容器种下 `hasBeenManuallyStopped` 隐形标记，Docker 29 开机时据此静默跳过 `unless-stopped` 容器）。现在激活信号走 `docker exec ... kill -s USR1 1`，不再经过 daemon 的 kill 代码路径；同时 deployer 启动 bootstrap 与人工 reconcile 增加自愈——state.json 声明的 active 容器若处于停止状态会自动 `docker start`（30s 节流），不再干等到超时 latch degraded 等人工。
- 发布流程落地"证据化验证"（SOP f6ac2407a）：新增轻量 `Release Check` release-PR 门禁、`Verify SHA Evidence` 测试证据继承判定（仅 release 修订 SHA 可跳过重型测试，7 天新鲜度、fail-closed）、`Promote Release` 升级为 job 级证据核验并独立重推导证据链。

## Fork Changes

- 部署器修复（PR #139，高风险路径 deployer，审计结论见该 PR）：
  - `ensureBackgroundActive`：`docker kill --signal=USR1 <id>` 改为 `docker exec <id> kill -s USR1 1`。信号仍送达应用 PID 1（行为不变，生产机实测零副作用），但不再触发 daemon 的 `HasBeenManuallyStopped` 置位；每次发布切换不再给新 active 容器种下重启丢容器隐患。
  - `waitForActiveDeploymentOnStartup` / `ReconcileWithOptions`：active 容器停止时自动拉起（两次尝试间隔 ≥30s）。只启动 state.json 声明的 active 容器；不改流量、不建容器、不切 slot；运行中但不健康的容器不碰；`docker start` 失败以明确原因 latch degraded。
- 发布流程（PR #140，流程维护，审计结论见该 PR）：
  - `backend-ci`：新增 `Verify SHA Evidence` job（push 到 main）。diff（对 first parent）只触及 VERSION + release notes 时，基于 Actions API 的 job 级数据判定测试证据继承（L1 parent 真跑全绿 push run；L2 parent tree 与已合并 PR head tree 相等且该 PR 上下文 run 真跑全绿；新鲜度 ≤7 天；任何异常 fail-closed 回退全量）。`Backend Test` 仅在判定成立时跳过，判定与审计链记录在 job summary。
  - 新增 `Release Check` workflow（<60s，release-PR 门禁）：基线无漂移、diff 包含性、release notes 校验、版本递增（不复用 tag、新基线从 ts.1）、go mod tidy、高风险路径机械判定（命中要求 PR 附审计链接）。非 release PR 秒过，可设为 required check。
  - `Release Preflight`：contracts / frontend / build 重型 job 移至合并后（push 上下文）执行；PR 阶段由 Release Check 承担。
  - `Promote Release`：Backend CI 验收升级为 job 级断言（真跑全绿，或 heavy job 跳过 + 证据链独立重推导成立），否则拒绝打 tag。

## Deployment And Rollback

- 通过 managed blue-green deployer 部署 Release workflow 生成的不可变镜像；部署前完成数据库备份并记录当前版本、容器、upstream 与健康状态。
- 本版本含部署器（控制面）行为变更：激活信号路径与启动自愈。回滚到上一完成版本 `v0.1.183-ts.2` 完全兼容（无 schema/状态格式变更，旧 state.json 直接可用）；出问题按控制面升级的 retry/quarantine 流程回退。
- 部署后的决定性验证建议：低峰窗口对生产机做一次受控重启，确认 active 容器开机后 30s 内恢复且 /health active（新自愈逻辑的直接验证）；可选演练 `docker stop <active 容器>` → 重启 deployer → 观察自动拉起（日志 action=auto_start）。

## Known Limitations

- 证据继承的新鲜度上限为 7 天：超过 7 天的 release 修订会回退为全量真跑（安全方向）。
- L2 判定窗口为最近 8 个已合并 PR；7 天内合并 PR 数超过 8 且目标 PR 不在窗口内时回退全量真跑（安全方向）。
- 本版本不改变已发生的标记状态：v0.1.183-ts.2 发布时种下的标记已由运维手动 `docker start` 清除（08-30），当前生产容器标记干净；本版本确保后续发布不再种标记。
