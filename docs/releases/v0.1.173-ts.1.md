# TokenSupply v0.1.173-ts.1

## Highlights

- Updates the fork to the upstream `0.1.173` line, including expanded Grok gateway capabilities, passive Channel Monitor v2, response-model-aware billing, multipart backup support, and several OAuth, validation, billing, and streaming fixes.
- Improves the Image Playground with a compact generation workflow, per-image deletion, retention that starts after generation finishes, and an administrator view for all users' tasks and occupied storage.
- Aligns operations-dashboard failure details with the availability cards that opened them, so excluded client/business events and count-token probes no longer appear as platform failures.

## Fork Changes

- PR #75 improves Image Playground task management. Users can keep editing prompts and generate while advanced parameters are collapsed, delete individual outputs, and use the more compact reference-image layout and gallery toolbar.
- Image output retention now starts only after a task reaches a terminal state. Redis indexes, cleanup inventory, storage accounting, legacy-record backfill, operation deadlines, and lock-token fencing make user and administrator task management durable under concurrent work.
- Administrators can browse all users' image-generation tasks, lazy-load previews, inspect occupied object-storage space, paginate results, and manually delete retained images.
- PR #77 adds exact `platform_failures` and `provider_failures` drill-down scopes. Platform-availability details require SLA-counted rows, exclude count-token probes, and still retain genuine stream failures recorded after HTTP 200.
- The provider-failure detail scope now matches the provider card's final-outcome definition without inheriting narrower legacy phase or owner filters. Generic error, excluded, all, and upstream lists keep their previous behavior.
- PR #76 preserves TokenSupply-specific service-tier usage snapshots, backup cancellation, customer-service settings, Image Playground settings, and other fork behavior while integrating the upstream `0.1.173` line.

## Upstream Changes

- Baseline: upstream `v0.1.172` (`155c49496026e86c17637614f5452cc7486db10c`) -> upstream `0.1.173` line at `0b3fe95afd20aba77ee7649b37febb8255fb57a5`, whose `VERSION` is `0.1.173`.
- Expands Grok integration with configurable model mapping, password/SSO/re-authorization flows, web search, Voice TTS/STT/Realtime, custom voices, video pricing, per-model quota handling, scheduling thresholds, cooldown behavior, and free-tier soft gates.
- Adds passive Channel Monitor v2 with 1-minute facts, fixed rollups, bounded backfill, retention, privacy defaults, health thresholds, administrator controls, and user-facing latency, success, cache, and error views. The default mode remains v1 until an administrator opts into v2.
- Adds response-model-aware billing and audit data, explicit search/audio/video pricing, Gemini native-image billing by the actual returned image count, and non-streaming OpenAI image accounting that is no longer cancelled when the client disconnects after upstream generation.
- Improves OAuth pending-account and refresh-token race protection, OpenAI routing hints, personal-subscription expiry handling, usage-percentage scheduling thresholds, legacy scheduler diagnostics, streaming `response.failed` delivery, and deduplication of latest-turn WebSocket security audits.
- Prevents pool-mode Gemini 429 responses from being promoted into an incorrect account-wide rate limit and preserves response-model audit data across the updated billing paths.
- Adds API-key quota and expiry validation, Composite-group image permission support, optional email-domain registration quotas, and a `nanoid` dependency update for `GHSA-2v37-7h3g-55p8`.
- Adds multipart upload and restore for large backup archives while preserving TokenSupply's backup lifecycle cancellation behavior.
- The upstream risk-control fail-closed change was reverted before the synchronized baseline; this release does not introduce that temporary behavior.

## Configuration And Migrations

- No new required environment variable is introduced. New behavior is controlled through administrator settings and group pricing fields.
- Migrations `217` through `219` add optional Grok video-model, Voice TTS/STT/Realtime, and search pricing fields. `NULL` keeps code defaults, explicit zero means free where documented, and positive values override the defaults.
- Migration `220` clears stale video prices from non-Grok and non-Composite groups after saving them in `groups_video_price_backup_220`. The cleanup is intentionally not reversed by an application-image rollback; the backup table contains the source values for manual restoration.
- Migrations `221` through `233` create Channel Monitor v2 configuration, one-minute facts, fixed rollups, histograms, watermarks, indexes, permissions, display settings, and privacy-preserving defaults. The 13 upstream monitor migrations were renumbered from `194-206` to `221-233` to follow the fork's existing migration history.
- Channel Monitor remains in `v1` active-probe mode by default. Administrators can opt into passive `v2`; user-facing throughput is hidden by default, while administrators retain full metrics.
- New optional settings cover email-domain registration quotas, Grok default model/base-URL mapping, cross-client model mapping, account scheduling thresholds, Channel Monitor mode, and throughput visibility. Existing installations receive conservative defaults.
- Image Playground storage records and Redis indexes are additive and lazily backfilled. They do not require a PostgreSQL migration or object-storage configuration change.
- New and old application images can coexist during managed blue-green deployment. Older images ignore additive columns and tables, but they do not undo migration `220`'s non-Grok video-price cleanup.

## Deployment And Rollback

- Publish only through the controlled Promote Release workflow after this Release PR and the merged `main` SHA pass Backend CI, the complete Release Preflight, exact-SHA audit, migration checks, and immutable-candidate verification.
- Deploy production separately through the managed blue-green updater after the tag, GitHub Release, image digest, checksums, and completion ledger are available.
- During deployment, verify migrations `217-233`, public and administrator health, response-model billing, Grok pricing paths in use, Image Playground creation/deletion and storage totals, Channel Monitor mode, and operations-card drill-down counts.
- Image rollback to `v0.1.172-ts.2` remains schema-compatible. If migration `220` removed intentionally configured non-Grok video prices, restore them explicitly from `groups_video_price_backup_220`; an image rollback alone does not restore that data.
- Channel Monitor v2 tables and additive group fields can remain in the database during rollback. Do not restore an older full database backup over live orders, users, balances, or usage created after deployment.

## Known Limitations

- The upstream annotated `v0.1.173` tag points to `29009f0b2ea14edf3b11ae2564fb617ff91a03b4`, immediately before upstream synchronized its `VERSION` file to `0.1.173`. TokenSupply follows the later tested upstream `0.1.173` commit `0b3fe95afd20aba77ee7649b37febb8255fb57a5`, so the fork version is correctly reset to `0.1.173-ts.1`.
- Channel Monitor v2 backfills incrementally. Its historical views can be incomplete during the first bounded backfill, and the exact equality between availability card sets and detail sets is not covered by a dedicated real-PostgreSQL end-to-end fixture.
- Image-task lease and legacy-backfill behavior is covered by Redis and race tests, but not by a live S3 timeout integration test. An administrator's first legacy backfill can transiently return busy when it meets an active task mutation; retrying is safe.
- External-provider behavior was not replayed against every live Grok, OpenAI, Gemini, or other upstream account during release preparation. CI and contract tests cover the integrated paths without consuming production credentials.
